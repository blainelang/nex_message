Nex Message (nex_message) controls how long Drupal messages remain visible. It works independently of Nex Editorial.

How notifications work

Settings are measured in seconds. Status messages default to 10 seconds; warnings and errors default to 0. Zero means never close automatically. A persistent message can still have a manual close button provided by the theme.

Timed messages show a countdown and a Keep open button. The countdown pauses while the pointer is over the message, while keyboard focus is inside it, and while the browser tab is hidden. Keep open stops automatic dismissal for that displayed message. Reduced-motion preferences disable the fade animation. Countdown ticks are not announced as live updates.

This applies to Drupal message containers, including AJAX messages, and explicitly tagged message panels. It does not change validation, publishing, or editing locks. Content Lock messages currently use their Drupal message-type default unless an integration explicitly tags them; there is no automatic detection by message text or originating module.

Settings and links

Use Configure on the Extend page, or Configuration → User interface → Nex Message. Choose a timeout for each message type. Warnings and errors should normally remain visible. Use Help on Extend or the help link on the settings form to return here.

Give a module its own message policy

The public API uses hook_nex_message_policy_alter(), data-nex-message for a named policy key, and data-nex-timeout for an explicit timeout. Keys such as editorial.saved are developer-defined labels, not module machine names.

Use a stable, namespaced key, such as editorial.saved, and implement hook_nex_message_policy_alter(). The module must also tag the message with that key. Defining a policy alone does not identify or change existing messages. The hook belongs in the sending module's .module file.

// Example integration in nex_editorial.module (not installed automatically):
function nex_editorial_nex_message_policy_alter(array &$policy, \Drupal\Core\Cache\CacheableMetadata $cacheability): void {
  $policy['overrides']['editorial.saved'] = 15;
  $policy['overrides']['editorial.pending_draft'] = 0;
}

// Where the module creates its message:
$message = [
  '#type' => 'html_tag',
  '#tag' => 'span',
  '#attributes' => ['data-nex-message' => 'editorial.saved'],
  '#value' => t('Draft saved for @title.', ['@title' => $node->label()]),
];
\Drupal::messenger()->addStatus(\Drupal::service('renderer')->renderInIsolation($message));

Direct override or permanent notice

For a one-off timeout, add data-nex-timeout="20" to the message wrapper. Use data-nex-timeout="0" to keep it visible. A render-array example:

'#attributes' => [
  'data-nex-message' => 'editorial.pending_draft',
  'data-nex-timeout' => '0',
],

The Nex Editorial draft notice uses an explicit zero timeout, so changing the warning default cannot hide it. No dependency is required just to output these harmless attributes; countdowns only operate while Nex Message is enabled.

Store module-specific settings in configuration

A module can supply its own configuration schema and settings form, then read those values in its policy hook. Add its configuration as a cache dependency using the second hook argument:

$config = \Drupal::config('my_module.settings');
$policy['overrides']['editorial.saved'] = (int) $config->get('saved_message_timeout');
$cacheability->addCacheableDependency($config);

This configuration example uses a hypothetical my_module.settings object; saved_message_timeout is not a built-in Nex Editorial setting. Define its schema, default value and settings form in the sending module, and validate nonnegative seconds. Add appropriate cache contexts for any policies that vary by route, language, role, or user. Site-wide policies are simplest.

Precedence and grouped messages

  • An explicit data-nex-timeout takes precedence over a named policy for the same element.
  • A named policy takes precedence over the message-type default.
  • If any tagged message in a grouped container has timeout 0, the whole container remains visible.
  • Otherwise, the longest valid explicit or named timeout in the container is used. Untagged messages share that container's lifetime.
  • Unknown message types remain visible; invalid overrides fall back to the default.

Always use translated strings with escaped placeholders or safe render arrays. Never concatenate user input into HTML. Avoid matching translated wording to decide timing.
